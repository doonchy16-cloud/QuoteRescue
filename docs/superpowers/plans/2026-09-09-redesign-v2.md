# QuoteRescue Redesign 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the first-keyword recovery engine with channel-safe, polarity-aware, temporally resolved decision and cadence policy that passes the V2 murder suite.

**Architecture:** Domain validation parses only explicit decimal inputs and structured permission state. `contact-policy.js` owns global/per-channel permission. `interpreter.js` owns clause facts and temporal/polarity resolution. `decision.js` reconciles structured stage/blocker with current facts. `context.js` composes those outputs. `messages.js` consumes the resolved decision and contact policy; it never invents cadence independently.

**Tech Stack:** Browser ES modules, Node 20 test runner, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-09-redesign-v2.md`

## Global Constraints
- No backend or external AI dependency.
- Global and per-channel permission decisions precede messaging.
- Same-day prior contact cannot create a Day-0 send.
- Close-loop/reactivation modes cannot create an active four-touch cadence.
- SMS <=320 chars; email subject <=90 chars and single-line.
- Existing tests plus `tests/murder-v2.test.mjs` must pass before merge.
