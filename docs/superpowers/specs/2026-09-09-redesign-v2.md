# QuoteRescue Redesign 2 Specification

## Goal
Replace the regex-first recovery interpreter with a deterministic policy pipeline that can represent channel permissions, clause polarity, temporal resolution, structured/text conflicts, recovery mode, and campaign cadence as separate concepts.

## Governing pipeline
`raw input -> domain validation -> contact policy -> context interpretation -> fact set -> contradiction resolution -> recovery decision -> priority -> cadence policy -> channel-safe copy`

No later layer may override or bypass an earlier safety decision.

## Contact policy
Represent global and per-channel permission separately.
- Global: `allowed`, `unknown`, `do_not_contact`.
- Per-channel: `allowed`, `unknown`, `denied` for `sms`, `phone`, `email`.
- Explicit global opt-out or wrong-recipient signals hard-block all outreach.
- Explicit channel restrictions deny only that channel.
- A denied requested channel may switch only to an explicitly allowed alternative; otherwise sending is blocked until permission is verified outside QuoteRescue.

## Context interpreter
Interpret clause-level meaning rather than first keyword match. For each candidate fact retain type, polarity, temporal state, evidence, and confidence.

Supported fact families:
- global opt-out / wrong recipient
- per-channel permission/restriction
- positive intent
- decline/inability to proceed
- competitor selected / competitor not selected
- budget blocker / resolved
- financing blocker / resolved
- trust blocker / resolved
- timing blocker / resolved
- spouse/partner blocker / resolved

Contrast/temporal markers such as `but`, `however`, `now`, `before`, `was`, `used to`, `resolved`, `approved`, `secured`, `fine`, `not a problem`, and `ready` affect which facts are current.

## Fact resolution
Current explicit facts outrank past facts. Resolved facts cancel older blocker facts of the same type. Negative or inability phrases around `move forward`/`proceed` outrank generic positive-intent phrases. Structured fields remain authoritative only when they do not conflict with clearly current resolved text; conflicts are always surfaced.

## Contradiction engine
Surface at minimum:
- lost/ghosted stage vs current ready/proceeding text
- considering-competitor stage vs customer chose us
- structured blocker vs current resolved blocker text
- requested channel vs contact policy
- allowed global permission vs explicit opt-out text

Material contradictions cap confidence at `medium`.

## Recovery modes
`active_followup`, `objection_resolution`, `nurture`, `reactivation`, `close_loop`, `blocked`.

## Cadence policy
- `blocked`: zero outbound messages.
- same-day prior contact: no Day-0 send.
- `close_loop`: exactly one close-loop opportunity.
- `reactivation`: exactly one reactivation opportunity.
- `nurture`: low-pressure reconnect cadence, not Day 0/2/4/7 chasing.
- `active_followup` and `objection_resolution`: full four-step cadence if contact policy permits.

## Numeric grammar
Accept decimal notation only. Reject hex, binary, octal, exponent syntax, Infinity, NaN, malformed tokens, and negatives where not allowed.

## Invariants
- No generated channel violates denied permission.
- No campaign contradicts `nextMove`.
- SMS <= 320 chars.
- Email subject <= 90 chars and single line.
- No invented scarcity, guarantees, fake urgency, or discount claims.
- Identical inputs produce identical outputs.
- Browser-only privacy boundary remains.

## Acceptance gate
1. Existing V1.1 tests pass.
2. V2 murder suite runs >=35,920 generated scenarios and passes.
3. Targeted opt-out, channel restriction, semantic negation/resolution, contradiction, numeric grammar, max-shape, privacy, and deterministic-fuzz attacks pass.
4. JavaScript syntax check passes in GitHub Actions.
